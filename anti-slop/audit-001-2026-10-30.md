# Review Bagian 2: Client dan Integrasi

Tanggal: 30 Oktober 2026. Mode antislop: AFTER, pilihan sesi pengguna.
Proyek yang diperiksa: `cinema-grpc`, bukan salinan `cinema-grpc-main`.
Tidak ada kode aplikasi yang diubah. File ini hanya laporan pemeriksaan.

## Kesimpulan

Fitur utama Bagian 2 telah diimplementasikan dan berfungsi pada integrasi lokal.
Belum layak dinyatakan selesai tanpa catatan karena gateway web dan skrip demo
memiliki masalah yang tidak terdeteksi oleh 22 automated test bawaan.

Review berfokus pada fungsi, kesesuaian tugas, dan bukti demonstrasi. Audit visual
di browser, responsive layout, serta pemeriksaan kontras tidak dilakukan; laporan
ini bukan pengesahan desain atau kelulusan seluruh UI Delivery Gate antislop.

## Bukti verifikasi

- Python proyek: 3.14.6, Windows x64.
- `python -m unittest discover -s tests -v`: 22 test lulus, 0,818 detik.
- Uji tambahan memakai server gRPC nyata, HTTP server lokal, dan database sementara.
- Balasan pertama BookSeat sengaja ditunda pada harness setelah operasi server
  benar-benar commit. Client menerima DEADLINE_EXCEEDED, retry dengan UUID sama,
  berhasil memperoleh hasil, dan database hanya memiliki satu booking.
- Mengakses `/static/../../requirements.txt` melalui HTTP menghasilkan status
  200 dan konten requirements proyek, membuktikan directory traversal.
- Dua koneksi SSE menerima snapshot lalu diputus. Setelah satu detik tanpa
  booking baru, dua subscriber tetap terdaftar di manager.
- Generator streaming client biasa ditutup: subscriber terkait dibersihkan.
  Kebocoran yang direproduksi berasal dari gateway SSE yang tetap menunggu gRPC.
- Skrip demo_fault_tolerance dijalankan dua kali pada database sementara sama.
  Pada percobaan kedua: kursi sudah terpesan, nol pemenang perebutan kursi,
  event UPDATE tidak diterima, tetapi output akhir tetap menyatakan sukses dan
  exit code tetap 0.
- Docker tidak tersedia di lingkungan ini. Build container dan demonstrasi dua
  komputer/container belum diverifikasi. Dua client lokal tidak membuktikan
  persyaratan dua komputer/container.

## Temuan teknis

Prioritas P1/P2 di bagian ini adalah prioritas review kode, terpisah dari tier
HIGH/MEDIUM/LOW aturan desain antislop. Masalah keamanan dan transaksi tidak
dipaksakan menjadi pelanggaran aturan estetika.

1. **[P1] Batasi akses static ke direktori static.**
   Lokasi: `web/server.py:104-108`.
   Path HTTP langsung digabung dengan direktori web tanpa normalisasi dan
   pemeriksaan batas direktori. `/static/../../requirements.txt` terbukti
   mengembalikan file proyek dengan HTTP 200. Dengan jalur serupa, file database
   atau file lain yang dapat dibaca proses bisa ikut terbuka, terutama karena
   web server bind ke 0.0.0.0. Perbaikan: resolve path lalu wajibkan hasil tetap
   berada di bawah direktori static sebelum memeriksa/membaca file.

2. **[P2] Bersihkan stream gRPC saat browser/SSE disconnect.**
   Lokasi: `web/server.py:179-197`.
   Handler menunggu event gRPC dan baru mengetahui putusnya koneksi browser ketika
   menulis event berikutnya. Tanpa booking baru, subscriber tetap terdaftar.
   Dua disconnect menyisakan dua subscriber dalam uji tambahan. Pergantian film
   dan penutupan tab berulang dapat menghabiskan batas 16 subscriber, lalu live
   update pengguna baru ditolak. Perbaikan: heartbeat/deteksi disconnect berkala
   dan pembatalan stream gRPC dalam cleanup yang tidak bergantung pada booking.
   Keterkaitan antislop: C-4, ketahanan ketika koneksi berubah.

3. **[P2] Demo timeout harus benar-benar memicu kegagalan pemanggilan.**
   Lokasi: `scripts/demo_fault_tolerance.py:69-87`, `client/cli.py:248-268`.
   Demo menerima balasan sukses lalu mengirim panggilan baru sambil menganggap
   balasan sebelumnya hilang. Ini membuktikan deduplikasi manual, bukan timeout
   dan automatic retry pada transport. Test retry bawaan menggunakan mock stub.
   Library retry sendiri terbukti berfungsi pada harness tambahan reviewer,
   tetapi bukti tersebut belum menjadi bagian demo/test proyek. Tambahkan uji
   integrasi dengan balasan tertunda setelah commit dan verifikasi callback retry,
   UUID identik, respons identik, dan jumlah booking satu.
   Keterkaitan antislop: R-36/C-5, klaim harus sesuai bukti yang diberikan.

4. **[P2] Gunakan UUID baru untuk operasi baru setelah penolakan final di web.**
   Lokasi: `web/index.html:423-431`.
   UUID baru hanya dibuat setelah booking berhasil. Jika kursi direbut pengguna
   lain dan respons REJECTED diterima, request ID tersebut sudah disimpan server.
   Memilih kursi lain lalu mengirim dengan UUID sama menghasilkan konflik
   ALREADY_EXISTS karena payload berubah. Pisahkan state operasi: pertahankan ID
   dan payload untuk retry hasil yang belum diketahui; buat ID baru untuk booking
   baru setelah hasil bisnis final, termasuk REJECTED.
   Keterkaitan antislop: C-2/C-4, alur pemesanan harus tetap bekerja setelah error.

5. **[P2] Demo harus memeriksa hasil dan gagal dengan jujur.**
   Lokasi: `scripts/demo_fault_tolerance.py:76-95, 183-198`;
   pola sama pada `client/cli.py:261-281`.
   Status CONFIRMED dicetak tanpa memeriksa success. Kursi demo C1/C2/C3 tetap,
   sehingga demo kedua memakai kursi yang sudah terpesan. Setelah menampilkan
   anomali concurrency dan kegagalan menerima UPDATE, skrip tetap mencetak sukses
   dan keluar dengan kode 0. Pilih kursi AVAILABLE atau database demo bersih;
   periksa semua respons/event dan berikan exit code nonzero jika kriteria gagal.
   Keterkaitan antislop: R-36/C-5, keluaran sukses tidak boleh dibuat tanpa bukti.

6. **[P2] Samakan versi Python container dengan spesifikasi proyek.**
   Lokasi: `Dockerfile.server:1`, `Dockerfile.client:1`.
   Keduanya menggunakan python:3.11-slim, sedangkan spesifikasi implementasi dan
   README menyatakan Python 3.14. Ini ketidaksesuaian versi, bukan klaim bahwa
   container pasti gagal. Gunakan image 3.14 yang sesuai dan verifikasi build.

## Catatan antislop dari pemeriksaan sumber UI

7. **[HIGH, R-32/R-39] Pemilihan film dan kursi tidak dapat dioperasikan keyboard.**
   Lokasi: `web/index.html:337-338, 406-410`.
   Kontrol dibuat sebagai div dengan onclick, tanpa native button, tabindex,
   role, atau penanganan keyboard. Tombol konfirmasi tidak cukup membantu jika
   pengguna tidak bisa memilih film/kursi melalui Tab/Enter. Gunakan button
   native dengan state disabled/selected dan fokus yang terlihat. Temuan berasal
   dari inspeksi sumber, bukan hasil pengujian browser manual.

- Timeout dan retry dengan request ID sama: tersedia; uji transport tambahan lulus.
- Streaming antarklien: tersedia dan teruji; lifecycle gateway SSE perlu dibetulkan.
- Integrasi dengan server: teruji lokal; server booking dan constraint tetap lulus.
- Petunjuk LAN dan container: tersedia; pelaksanaan di dua mesin belum terbukti.
- Commit dari anggota 2: pada checkout yang diperiksa, tambahan Bagian 2 masih
  untracked dan perubahan lain belum di-commit; commit terakhir masih Bagian 1.
  Ini hanya keadaan checkout lokal, tidak membuktikan isi remote repository.
